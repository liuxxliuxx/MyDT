# V3.2.1 执行效率优化

本轮修改执行方式，保留模型参数、损失定义、原始数据顺序、随机掩码、全局32个起点／新packet、FP32精度和0.5秒积分步长。跨维度演化、双人持续反馈和长时记忆公式不变。`staged_revision` 不变，checkpoint 额外记录 `execution.mode` 和 `execution.revision`。

## 实现

- `reference`：保留原执行方式，用作数值和速度对照。
- `optimized`：对已经验证的未来查询时间表，避免在每个积分步重复做GPU张量校验和CPU读回；同一预测内复用固定的衰减率计算图。端点损失向量化，仍先逐query计算 CE、有效VAD坐标均值和intensity之和，再按有监督的query取均值。不能把它改成全体VAD坐标的统一均值。
- `compiled`：在上述优化上，编译完整的一个指数中点积分步，包括两次动力学系数计算。保持每0.5秒更新系数，保持原积分时间格和分数秒查询语义。没有启用TF32、混合精度或CUDA Graph。
- 优化模式按dtype/device合并梯度通信与有限值检查。两卡仍按原规则求梯度平均，缺失梯度的处理与原入口一致。

编译的是积分函数，未将模型包装成带新参数前缀的模块；原checkpoint参数名称、构造信息和优化器参数顺序保持兼容。`--execution compiled` 可以在恢复现有阶段时覆盖执行模式。相同阶段内的游标、随机状态、固定起点生产者和优化器继续恢复。首次遇到新的训练阶段或张量形状会触发编译，编译耗时单独记录，不能混入稳定速度收益。

## 实测

服务器1、物理GPU2、conda `lzh_DDG`。相同checkpoint、16个起点、六个未来时距及端点标签，保持FP32、关闭TF32。编译和数值检查与原训练并行，稳定测速时短暂暂停两张卡上的原训练进程，测速结束后在 `finally` 中恢复。

| 执行方式 | 前向反向中位耗时 | 相对原版加速 |
| --- | ---: | ---: |
| reference | 1.84197秒 | 1.00倍 |
| optimized | 1.75579秒 | 1.05倍 |
| compiled | 0.45891秒 | 4.01倍 |

这组时间包括相同向量与端点标签损失，不包括真实双卡通信、完整对话重放和验证。切换后的实际训练步速另行报告。编译版首次模型准备、编译和预热合计56.61秒。

编译版单步预测最大绝对差异 `2.98e-8`，梯度最大绝对差异 `5.12e-9`，梯度相对L2差异 `4.92e-7`。固定相同20批起点、相同新优化器与学习率连续更新后，参数最大绝对差异 `8.18e-7`，预测最大绝对差异 `1.04e-7`。这证明短程误差很小，不保证完整训练后的权重逐位相同。

同一checkpoint完整重放24段验证对话，结果如下。这里比较执行方式的数值差异，没有更新任何模型权重。

| 验证协议 | reference宏平均MSE | compiled宏平均MSE |
| --- | ---: | ---: |
| 固定起点 | 0.002080533331923 | 0.002080533320145 |
| 候选模型自身起点 | 0.002019971952322 | 0.002019971935722 |
| 连续缺失输入 | 0.002017132183756 | 0.002017132173658 |

三种协议MSE差异均小于 `1.7e-11`；重新生成的起点最大向量差异为 `1.49e-7`。本地91项相关测试、服务器44项回归测试均通过。GPU2、3上的真实NCCL梯度合并检查逐元素一致，编译版四阶段各1步的真实数据训练和checkpoint保存均完成。
