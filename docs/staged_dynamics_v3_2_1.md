# V3.2.1 状态校准与固定起点传播训练

本轮只修改状态监督与训练流程，保留 V3.2 的状态结构、跨维算子和双人耦合结构。旧 checkpoint 作为显式初始化，不恢复旧优化器。情感编码器、情感标签头及教师保持冻结。

## 防止提高观测覆盖来降低当前误差

`state_anchor_loss` 比较校正后的 `baseline + fast + slow` 与冻结教师的当前向量。仅有新有效证据的角色参与，并对可靠度停止梯度。fast 和 slow 不分别拟合当前观测。

以下参数在所有阶段保持初始化时的值，并在验证和保存 checkpoint 前逐元素检查：

- `fast_correction_logits`、`slow_correction_logits`：观测校正速率。
- observer 的 `reliability_head`、全部 affect 编码分支：可靠度及情感坐标。
- `event_strength`、`coupling_strength`：事件／行为输入增益。
- `baseline`：状态的参考中心。

事件／行为映射本身可以在校准和联合阶段训练。因此仍需预测验收，不能仅靠锁定校正参数断言模型没有走捷径。

每次验证同时运行三个协议：

1. **fixed**：永远使用初始化模型形成的同一批完整起点，仅比较候选传播器。
2. **live**：使用候选模型的确切权重，从对话开头完整重放，得到部署时会产生的起点，再预测未来。
3. **gap**：同样完整重放，但每32秒的最后8秒丢失全部新观测、事件和行为，检查模型依赖历史传播的表现。

`input_conditioned_prior` 已包含当前声明的事件和行为，只有 affect 校正尚未执行，不能把它称为无未来输入的 open-loop 指标。真正的未来预测不读取查询期间的观测、事件或行为。

## 阶段与起点更新

- calibration：冻结传播器，只训练事件／行为头及相应状态更新映射；同时优化当前状态向量和多时距未来目标。
- fixed：冻结状态更新映射，固定完整起点，只训练传播参数。
- joint：用较小学习率共同训练传播和状态更新映射，校正速率等锁定参数仍不开放。
- readapt：joint之后重新从头重放训练对话、生成新起点，再冻结更新映射训练传播器。

fixed/readapt 的每个训练块都有不可变的起点生产者哈希，下一块重新建立起点。训练块之间不沿用旧版本的起点。顺序校准／联合训练在块边界也会重新计算已经消耗的对话前缀。块内按完整对话顺序执行 TBPTT，优化步之间保留并截断状态梯度。

新起点适配并不保证分布从此不变；传播器更新也会影响部署起点。因此最终是否可部署，以候选权重重新生成的 `live` 验证为准。checkpoint 保存对应验证哈希，不使用固定缓存验证代替部署验证。

## checkpoint 选择与恢复

当前重建误差不能选 best。只有 fixed/readapt 阶段完成验证，且以下条件同时通过，才保存 `best.pt`：

- 固定起点的宏平均预测 MSE 相比初始化传播器至少下降0.5%，并优于保持。
- 候选模型自身产生的起点上，预测优于保持，绝对 MSE 不比初始化完整模型差超过2%。
- 连续缺失场景的绝对预测 MSE 不比初始化模型差超过2%。
- 校正／输入增益锁定检查通过，live 起点生产者哈希等于候选权重哈希。

排名分数为固定起点和自身起点两种预测误差相对各自初始化值的等权平均。分域、分时距误差总和与有效元素数保留；宏平均先按每个时距内的可用数据域等权，再按时距等权。语义 CE、准确率、VAD 与 intensity 在真实标注时间单独记录。通过上述门槛不等于已经优于训练均值收缩，也不等于情感语义能力已经提升。

`last.pt` 始终用于恢复；不通过预测门槛的中间模型不会被标成部署 best。checkpoint 包含完整模型、初始参考模型、当前起点生产者模型、分阶段位置、优化器、每张卡的对话游标与随机状态。外部预训练文件移走后仍可恢复。数据和卡数变化会拒绝原优化器恢复。

## 速度与数据预算

冻结的情感编码器按多packet批次运行，持久缓存 affect、可靠度、模态有效性和事件／行为头的输入。事件／行为输出仍由当前可训练头重新计算。缓存绑定编码器权重、完整数据清单哈希、协议版本、模态子集和 FP32 精度，不允许跨提取来源静默复用。

固定起点阶段每步32个起点，在两卡上各16个，同时计算未来1、2、4、8、16、32秒预测。顺序阶段每步32个新packet，每卡最多保留16秒的梯度链。向量与状态为 FP32，关闭 TF32；没有缩短预测时距、减少积分精度或扩大有效 batch 来制造速度提升。

固定起点阶段复用样本，与顺序阶段消耗新packet的统计含义不同，日志明确区分。每轮起点库按域从训练对话中确定性选取一批，循环轮换，保留实际索引。这次是新的训练协议，不能把相同优化步数称为与旧训练完全相同的数据访问预算。验证只读取原val；test/OOD不参与选择。

`scripts/benchmark_staged_dynamics_v3.py` 比较完全相同起点、未来目标、mask及归一化下的串行／批量预测前向反向，并检查输出与梯度误差。该加速比仅代表预测核心，总耗时还包括缓存生成、完整对话重放和验证。

执行入口另支持 `--execution optimized` 和 `--execution compiled`，分别启用减少同步／向量化损失／梯度合并，以及积分步编译。它们保持本训练协议，可从同一阶段checkpoint恢复；执行模式写入checkpoint和日志。性能与数值验收见 [2026-09-10执行优化记录](staged_execution_optimization_2026-09-10.md)。

## 启动

入口为 `python -m emotion_ssm.train.dynamics_staged_v3 --config CONFIG.json`；双卡使用 `torch.distributed.run --nproc_per_node=2`。GPU2、3由外部 `CUDA_VISIBLE_DEVICES=2,3` 限定。

`scripts/launch_staged_dynamics_v3.py` 先跑1000步诊断：100步校准、400步固定起点、两轮50步联合＋200步重新适配。诊断产生通过预测门槛的 best 后，自动执行10000步正式训练：1000步校准、4000步固定起点、四轮250步联合＋1000步重新适配。若诊断没有通过门槛，停止在诊断结果，不消耗正式预算，也不自动进入生成训练。
