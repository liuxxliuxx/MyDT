## 训练内容

`emotion_ssm/train/dualtalk_baseline_control.py` 的实际路径是：加载官方预训练权重，再对 DualTalk 的 train 目录微调。数据集构造只读取 DualTalk train/test，不读取三数据源配置。`control.json` 记录训练3轮、调度器总周期100轮、关闭 conditioning 和 state consistency。第3轮为 global_step=8880。AdamW 学习率1e-4、weight decay=1e-4；优化原 DualTalk 主干的可训练参数。

EmotionTalk 和 IEMOCAP 在情感方案中主要用于上游情感观测和动力学训练，并没有为这组 baseline 或生成器直接增加 FLAME 监督样本。因此“三数据集情感模型”与“DualTalk baseline”的数据利用方式不同。

服务器 `model/dualtalk_baseline.pth` 大小为 2589355927 字节，SHA-256 为 `b9af0f6c1d732357af52576fde7c2be5cf4bb4ff9df6a8b4370dd4115a32acd6`，与官方 Hugging Face 仓库 ZiqiaoPeng/DualTalk 的 DualTalk.pth LFS 摘要完全一致。可以排除此次对照误用了非官方初始权重。

使用完整评估集，test 为2580个完整200帧片段，OOD 为1876个片段。以下 total 是 expression、jaw、neck、velocity 四项误差之和，不是单一部位的 MSE。

## 官方公开训练加载器的确定缺陷

官方 ZiqiaoPeng/DualTalk 的 dataset_train.py（读取版本 blob SHA：0c9488fa614ccc9023e70c8104fe506aef99e4ee）在每个文件内只创建一次 `file_meta_dict`，随后在片段循环内不断修改同一个字典并执行 `data.append(file_meta_dict)`。同一个文件的所有列表项最终引用最后一个片段。例如本应是片段0、1、2，实际成为片段2、2、2。

本地和服务器保留的原始加载器有相同写法。当前 baseline control 和情感生成训练使用的 `emotion_ssm/data/dualtalk.py` 在片段循环内新建字典，避免了这个问题。

只读检查服务器训练数据：9706个定向 npz，9212个有效定向流，可得到23684个完整200帧片段。如果使用公开旧加载器，最终只有约9212个不同片段内容被重复，前面的14472个片段（61.1%）不会作为独立训练内容出现。这里的“不同”按文件内片段位置统计，不保证跨文件内容唯一。

这证明公开代码存在覆盖范围问题；尚不能证明作者发布权重时使用的内部训练版本就是这份代码，也不能将此次17.98%的收益全部归因于这个缺陷。baseline control 与情感模型均使用新加载器，因此该缺陷不能解释两者之间0.31%的差距。

## 预处理和评估协议

官方公开训练加载器先通过 Wav2Vec2Processor 对整段音频归一化，再切成片段。当前加载器对每个原始音频片段独立归一化。当前微调会适应这一预处理方式。

官方公开测试加载器使用整段配对序列；当前对照评估使用完整200帧片段、丢弃尾部不足200帧的部分，并按元素汇总误差。官方权重与 baseline control 在这次对照中使用同一个自定义评估函数，因而上述表格是当前协议内可比较的权重对照，不能直接称为对官方论文评测的完全复现。

官方训练本来就有 expression、jaw、neck、velocity 四项损失，不能把收益解释为当前脚本新增了速度监督。优化器、批大小、shuffle、重新初始化的学习率调度及最佳权重选择方式也存在变化；缺少逐项控制实验，尚不能量化每项贡献。

## 情感模型的比较范围

旧版服务器2模型的 DualTalk 生成器从第1轮开始训练，conditioner 前10轮冻结、第11轮解冻。新版本生成器前10轮冻结，两者不能混用训练轮数解释。旧版第3轮时上游情感编码器仍冻结，后来发现的编码器退化不能倒推为第3轮略差的原因。

后期旧模型的观测编码器退化、最终生成阶段缺少上游训练时的部分模态、分块状态重置、情感一致性目标缺少稳定锚点等问题，见 emotion_training_audit_2026-09-06.md。额外的情感数据需要通过这些连接传递到 FLAME 生成损失；数据源增加不自动产生可利用的生成收益。

## 数据重叠检查与剩余不确定性

train/test/OOD 之间没有共同的 npz 文件名，也没有共同的 `(exp.npy CRC, 大小, pose.npy CRC, 大小)` 联合指纹。该检查排除了这一层面的完整文件重复，不能证明说话人、会话或原始视频完全不重叠。

训练脚本使用 test 划分做验证和最佳权重选择；未发现将 test 数据送入训练梯度的路径，但用于选模型的 test 不宜再作为完全独立的最终测试。OOD 同时有11.89%的改善，不能将全部提升解释成 test 选择偏差。

建议后续在统一加载器、预处理、数据划分、批大小和主干更新次数下，对照官方初始化、baseline 微调、加入冻结情感条件、加入可训练情感条件。记录并固定实际评估 checkpoint 的轮次和摘要，并在多随机种子及独立测试划分上判断情感模块的额外收益。
