# Avatar指标统计与数据预取优化

实验：`runs/avatar_old9750_20260911_gpu23`，服务器1物理GPU2、3。

只修改两个执行环节：

- `DeferredReconstructionTotals`保留逐块FP64误差归约、时间顺序和计数规则，
  将GPU标量读取从每块多次减少为每个优化步读取一次汇总。
  重建损失、反向图和梯度同步路径保持原实现。
- `PrefetchSegmentCursor`用一个CPU线程提前加载一个优化步的数据。
  仅允许明确声明不使用全局随机数的固定数据读取器。声音增强、模型计算和CUDA操作仍由训练线程执行。
  `seen`只计入已经交付训练的包；后台读出的下一批不计入断点位置。
  文本和其他未来输入可以被提前读入CPU，但不会提前送入观测器、状态更新或生成器。

执行开关独立于数据和优化协议：

```json
"generation_execution": {
  "defer_metrics": true,
  "prefetch_batches": 1
}
```

完整断点恢复时只接受上述执行开关覆盖。学习率、训练预算、有效块数、损失、
可训练参数、模型结构、数据划分仍以checkpoint为准。AdamW的非capturable步数计数器
保持CPU位置，动量张量随参数恢复到GPU；避免把计数器全部搬到GPU而改变原先执行方式。

初次部署在本地和服务器均通过45项测试，加入测速验收门控测试后，服务器完整测试为46项通过。测试包含：

- 原版和延迟指标累加的逐位一致性，含跨块边界和无效帧。
- 双rank的数据顺序、跨epoch、缺失目标、尾块、预取peek和断点游标。
- 预取线程不改变Python、NumPy、Torch随机数状态；读取错误回传主线程。
- 三组各20步训练对照：只改指标、只改预取、两项同时修改。
  每一步核对权重、梯度、AdamW状态、会话状态、指标和随机数状态，要求逐位一致。
  测试生成器包含Dropout与NumPy随机增强，并保留梯度检查点。

真实模型对照分两部分：

1. `throughput_probe`：原训练继续运行时，利用剩余显存在同两张卡运行固定权重的
   前向/反向/梯度同步对照。不执行AdamW更新，故结果不能称为完整训练的提速。
   使用相同smoke断点、相同样本和随机状态，前5步预热不计入均值。
2. `throughput_benchmark`：原训练第1000步完成完整验证及checkpoint保存后，停止
   此Avatar的旧进程，其他动力学任务继续。四个执行组合从同一断点各训练20步，
   最后重复一次原执行方式，使用前后两次参考耗时的平均值，减小并发负载变化的影响。
   对输入、权重、梯度、优化器、AMP、会话状态、随机状态和逐步指标进行严格核对。
   通过后从组合优化分支的第1020步继续正式训练，预算仍为30000步。
   若对照失败，自动恢复原执行开关，从第1000步完整断点继续训练，并记录错误。

初次探测代码位于实验内`code_throughput_v1`；正式切换使用`code_throughput_v2`，增加了原版复测及切换门控。
模型、损失、指标和预取实现两份相同，原`code`保留。
切换前日志为`formal.log`；切换后日志为`formal_optimized.log`。
`throughput_status.json`记录探测、等待断点、切换、对照与继续训练的实际状态。
`throughput_probe/comparison.json`与`throughput_benchmark/comparison.json`分别保存两类速度结果。
`throughput_arm_status.json`记录原版复测与切换流程的准备状态。

此流程只负责本次训练的安全切换及阶段衔接，没有创建定时巡检。
